# Data Model

MongoDB (native Rust driver, BSON documents, no ORM). *As of 0.3.0-rc.381* the
server maintains indexes on **39 collections plus 8 stats-rollup collections**
(`crates/db/src/indexes.rs` is the authoritative list; models live in
`crates/db/src/models/` and — for the fleet subsystem — `crates/remote_control/src/models.rs`).

Everything is scoped by `tenant_id` (multi-tenancy) except the global registries
called out below.

| Collection | Purpose · key fields / indexes |
|---|---|
| `tenants` | Organizations. Unique `slug`; `owner_id`; plan + Stripe linkage |
| `users` | Accounts. Unique `email`, `username`; text index on `display_name`+`username`. ⚠️ Unique `email` is a **reservation**, so it holds only an address the account has *proven* (activation, or a provider that verified it) — an unproven claim goes to the non-indexed `unverified_email` and the row takes a `.invalid` placeholder |
| `tenant_members` | Membership + role assignment. Unique `(tenant_id, user_id)` |
| `roles` | Permission bitfield (`u64`; 33 bits defined since FR-90's `HIVE_RUN` — [permissions.md](permissions.md)). Unique `(tenant_id, name)`, ordered by `position` |
| `rooms` | Hierarchical tree (text + voice/video): `parent_id`, unique `(tenant_id, path)`, sparse-unique `meeting_code`; text index on `name`+`purpose`+`tags`. Optional `binding {module, ref}` — another module owns what the room *means* (FR-90: an agent session's room, `secret`, path `hive-<session id>`); chat stores it and never interprets it |
| `room_members` | Per-room membership |
| `messages` | Chat. Thread via `thread_id`, pins, embeds; text index on `content`. `author_type` `user` (default) · `bot` · `webhook` · `system`; a non-user author carries its own `author_display` (FR-90: `Claude · <device>`), which is read **only** when `author_type` is not `user` — a person cannot rename themselves through it. Optional `binding` (FR-90: a turn's stub, edited in place when the turn ends) |
| `reactions` | Unicode + custom-emoji reactions, keyed by `message_id` |
| `recordings` | Call recordings; storage provider `S3`/`MinIO`/`Local` |
| `call_sessions` | Call lifecycle rows (**730 d** TTL on `started_at` — the conference module's index set, not 90 d) |
| `call_chat_messages` | In-call chat (no secondary indexes) |
| `files` | Versioned uploads; uploader, room linkage |
| `invites` | Shareable/email/batch invites; unique `code` |
| `custom_emojis` | Tenant emoji sets |
| `notifications` | @mention & system notifications; `is_read`. FR-90's `approval_request` names a session that waits for a driver, never the call. ⚠️ A `notification_type` a build does not know reads as `other` — one new kind must not fail a user's whole list on an older pod mid-roll |
| `push_subscriptions` | Web-push endpoints (VAPID) |
| `background_tasks` | Export/processing pipeline; TTL-expired |
| `activation_codes` | Email activation; TTL on `expires_at` |
| `stripe_events` | Stripe webhook dedupe/audit. **FR-102 P4**: an event whose processing failed is un-marked, so Stripe's retry is processed rather than skipped |
| `billing_events` | FR-102 P4 (`saas`): what Stripe billed — one row per webhook event of the six billing kinds (`subscription_created` · `subscription_updated` · `subscription_deleted` · `invoice_paid` · `invoice_payment_failed` · `trial_will_end`) and one per paid invoice the operator's backfill read: `tenant_id`, `kind`, `plan`, `seats`, `amount_cents` (invoices: what was billed, after coupons, before tax; `null` on a subscription event, never 0), `recurring_cents` (the non-proration subscription lines — the basis of billed MRR), `interval_months`, `currency`, `period_start` / `period_end`, `stripe_id` (`in_…` / `sub_…`), `subscription_id`, `status`, `reason`, `cancel_at_period_end`, `event_id` (absent on a backfilled row), `source` (`webhook` · `backfill`), `ts`, `recorded_at`. **Never a card, an address or a name.** Indexes: sparse-unique `event_id`; unique `(kind, stripe_id)` partial on `kind: invoice_paid` (the webhook and the backfill meet on it); `(tenant_id, ts)`; `(kind, ts)`. No TTL — **kept with the org**: `meshharbor_core::growth::purge_tenant` takes them; the monthly totals frozen into `growth_daily` carry no org and stay ([growth-observability.md](growth-observability.md#revenue-what-stripe-billed-p4)) |
| `subscribers` | FR-39/FR-58 (`saas`): the public updates list — normalised `email` (unique), `source`, `confirmed` + `confirm_token` (double opt-in), `unsubscribe_token` (unique, never expires), `created_at` · `confirmed_at` · `unsubscribed_at`. Rows are kept and stamped on unsubscribe, never deleted (the consent record). **FR-102 P5**: `unsubscribed_via` (the slug of the issue whose link ended the subscription, written once; cleared by fresh consent) and `suppressed_at` + `suppressed_reason` (`bounce` · `spamreport`: SendGrid reported a hard bounce or a spam report — never mailed again until fresh consent). No TTL ([newsletter.md](newsletter.md)) |
| `newsletter_issues` | FR-58 (`saas`): one issue — `slug` (unique), subject, preheader, `body_md`, hero/CTA, `status` (`draft` → `sending` → `completed`), the send claim, `counts` stamped at completion, `sent_at`. **FR-102 P5**: `campaign` (the `utm_campaign` its links carried, `nl-<slug>`; absent with the tags off) and `delivery_events` (its delivery events are recorded: every message named the issue for SendGrid and this server verified the webhook) — stamped when the fan-out starts; `audience` (a **test** issue's 1–20 addresses: the send goes only to the confirmed subscribers among them; fixed with the draft). No TTL |
| `newsletter_sends` | FR-58 (`saas`): the per-recipient delivery ledger — unique `(issue_id, subscriber_id)` (the at-most-once invariant), the address as mailed, `status` (`claimed` → `sent` · `failed` · `suppressed`; `sent` = accepted by SendGrid), `error`. **FR-102 P5**: `delivery {delivered_at, bounced_at, bounce_type, dropped_at, spam_reported_at, reason}` — what SendGrid's signed Event Webhook reported, each time the earliest (`$min`, so a replay writes nothing); **never an open or a click**. Index `(issue_id, status)`. No TTL — the send record, as FR-58 ([growth-observability.md](growth-observability.md#the-newsletter-delivery-per-issue-tags-and-unsubscribes-p5)) |
| `consent_requests` | Remote-session owner-consent capability tokens |
| `used_tokens` | Single-use JWT `jti` burn list (1 h TTL) |
| `growth_exclusions` | FR-102 P1c: the platform admin's explicit exclusion list — `{kind: tenant\|user, id, reason, by, at}`, unique `(kind, id)`. The implicit exclusions (every platform admin, every org an excluded user owns) have no row; `meshharbor_core::growth::ExclusionSet` folds both into the one set every growth number applies ([growth-observability.md](growth-observability.md)). No TTL |
| `growth_content` | FR-102 P7b (`saas`, its index set in the module): one row per blog post, `_id` = the post's path (`/blog/<slug>/`) — `url`, `title`, `published_at`, `updated_at`, `first_seen_at`, `last_seen_at`, `in_feed`, and `inspection {verdict, coverage_state, indexing_state, page_fetch_state, robots_txt_state, last_crawl_time, google_canonical, inspected_at, attempted_at, error}` from Google's URL Inspection — `inspected_at` the time the verdict was read (absent until one was), `attempted_at` the newest attempt. Read from the site's own Atom feed once a day by the content puller — only an Atom feed changes the list: a 404, a redirect or a page that is not a feed is a failed read; a post that leaves the feed is kept with `in_feed: false`; a failed inspection keeps the last good verdict and its `inspected_at` and records `error`. Read by the host through `meshharbor_services::dao::growth_content`. Index `(published_at desc)`; no TTL (our own content, no person) ([growth-observability.md](growth-observability.md#search-search-console-bing-and-the-blogs-posts-p7b)) |
| `growth_digests` | FR-102 P1d: one daily digest per closed UTC day, `_id = "YYYY-MM-DD"` — `status` (`computing` → `sent` · `stored` · `failed`), `claimed_at`, `computed_at`, `sent_at`, `attempts`, `error`, `recipients` (a **count**, never the addresses), `excluded {users, tenants}`, `sections` (the typed sections, serialised whole). The unique `_id` is the once-only claim: the insert decides which pod computes and mails. **25-month TTL** on `computed_at` |
| `growth_daily` | FR-102 P3: the frozen daily totals — one row per `(source, metric, dims, day)`, `_id = "<source>:<metric>:<k=v,…>:<day>"` (since P6 every part percent-escapes `%` `,` `=` `:`, so a client-chosen value cannot forge another row's id), `{day: "YYYY-MM-DD", source, metric, dims, value}`. `install:fetch` with `dims {asset, client, os}` from the fleet module's fetch counters, upserted with `$inc` — **never a User-Agent, never an IP**, and never the updater's own checks; since **P3c** `client` is `internal` for a fetch from the operator's internal networks (`growth.internal_networks`, matched in memory against the limiter's client address, which is then dropped), in place of its class; **P3b**: `install:wizard_step` with `dims {step, outcome, os}`, the value the number of **distinct** opted-in wizard runs that ended that step with that outcome that day, written with `$set` by the host's nightly freeze from `setup_diagnostics` (the last three closed days, idempotent; a day with no runs holds no rows) and never rewritten once past that window, so the counts outlive the 90-day rows. **P6**: `source: purestat`, written by the `saas` puller with `$set` (idempotent; write-then-prune per pulled day) — `dims.by` `site` · `campaign` (the normalised key `source`/`medium`/`campaign`/`content`) · `path`, metrics `visitors` `visits` `pageviews` `reads` `goal.<name>`; zeros are not stored, and a day older than 7 days is frozen, never rewritten. **P4**: `quota:collision` with `dims {tenant, limit}` — a plan-limit collision per org, limit and UTC day (`$inc`, from `meshharbor_core::quota`; refused or let through in `warn`), which **goes with the org** (`purge_tenant` takes every row with a `tenant` dimension); and `source: billing` — the monthly billed totals frozen from `billing_events` (`day` the month's first day, `dims {currency, period: month}`, metrics `mrr_cents` `paying_orgs` `new_cents` `new_orgs` `expansion_cents` `contraction_cents` `churned_cents` `churned_orgs` `net_new_cents` `invoices_paid` `billed_cents`; `$set` by the nightly freeze, no org, rewritten only by the operator's backfill). **P7a**: `source: github` — the `saas` GitHub puller's cumulative snapshot of each closed UTC day (`dims.by` `repo` with `stars` `forks` `watchers` `downloads` (the product's releases, their `.asc`/`.sha256` sidecars left out) `helper_downloads` (the vendored builds and caches CI downloads); `release` (with `kind: product|helper`) and `flavour` (product assets) with `downloads`; `dims.repo` always), `$set` and never rewritten after its 01:00–07:00 window, differenced by the readers (a missing snapshot makes every delta across it null); and with a token `source: github_traffic` — `by: traffic` views / clones per day (13 closed days re-pulled, then frozen) and `by: referrer` GitHub's 14-day ranking under the day it was read after. **P7b**: `source: search_console` — Google's FINAL days only (Pacific-time dates), `by` `site` · `page` · `query` · `page_query` with `clicks`, `impressions` and `position_x100` (the position weighted by impressions ×100; CTR is derived, not stored); `source: bing` — Bing's daily site `clicks` / `impressions`; `source: bing_weekly` — Bing's weekly buckets per `query` and `page` with `clicks`, `impressions`, `avg_impression_position_x10`, `avg_click_position_x10`, under the bucket's date. Index `(source, metric, day)`; no TTL (aggregates about the product, no person) ([growth-observability.md](growth-observability.md)) |
| `growth_keys` | FR-102 P8 (D12): the growth surface's machine keys — `{kind: ingest \| read, label, prefix, hash, created_by, created_at, revoked_at, last_used_at}`. **Only `hex(SHA-256(key))` and a display prefix (`rgi_AbCd1234` / `rgr_…`) are stored**; the key itself is answered once, at mint. An `ingest` key opens `POST /api/admin/growth/ingest/{posts,snapshots}` and nothing else; a `read` key (P10) opens the `GET /api/admin/growth/*` views and nothing else — never a write, never `/keys` or `/exclusions`; revocation is a timestamp. Unique `hash`, index `(kind, created_at)`; no TTL ([growth-observability.md](growth-observability.md)) |
| `growth_weekly` | FR-102 P10: one weekly roll-up per closed ISO week, `_id = "YYYY-Www"` — the daily digest's row shape (`status`, `claimed_at`, `computed_at`, `sent_at`, `attempts`, `error`, `recipients` as a **count**, `excluded`, `sections`) and the same once-only claim, in a collection of its own so the daily store's "latest" never meets a week. `sections` = the week's headline against the weeks before, and the funnel, cohorts, campaigns, channels, newsletter and alerts reports computed for that week. **25-month TTL** on `computed_at` ([growth-observability.md](growth-observability.md#the-read-key-the-weekly-roll-up-and-alerts-p10)) |
| `session_feedback` | FR-102 P9b (`remote`): a person's rating of one remote session, asked by the viewer after a session of 30 s or more — `{session_id, tenant_id, user_id, agent_id, rating: up \| down, reasons: [codes], ts}`; `reasons` from the fixed vocabulary `lag` · `picture` · `input` · `could_not_connect` · `other`, **no text field**; `user_id` from the authenticated request, `agent_id` denormalised from the session row, `ts` the server's clock. Written only by `POST /api/tenant/{tid}/session/{sid}/feedback` from the session's controller or a watcher, never before 30 s after the request, the empty 404 while `MESHHARBOR__GROWTH__FEEDBACK=false`. Indexes: **unique `(session_id, user_id)`** (one rating per session **per person** — a rating is one person's experience, so the controller and each watcher rate once each; the arbiter between two posts by one person), `(tenant_id, ts)`, `(user_id)`; **25-month TTL** on `ts`; `SessionFeedbackDao::purge_user` takes a person's rows with the account ([growth-observability.md](growth-observability.md#the-post-session-rating-p9b)) |
| `touch_presets` | FR-111 P4a (`remote`): an org's on-screen control presets — `{tenant_id, name, controls, created_by, updated_by, created_at, updated_at}`, where `controls` is the viewer's own `TouchPreset` list (rows of buttons, d-pads, sticks; a button's action is `keys`, `mouse` or a `macro` of press / release / tap steps with waits). Read by any member, written with `MANAGE_TENANT` through `TouchPresetRequest::validate` (keys only on the keyboard page, bounded counts, sizes and waits, labels as text). Index: **unique `(tenant_id, name)`**, which also serves the name-ordered listing. Deleted, not tombstoned: nothing holds a preset's id but a browser's remembered choice, which falls back to off ([touch-controls.md](touch-controls.md#the-orgs-presets-p4)) |
| `growth_quality_daily` | FR-102 P9a: remote-desktop quality per UTC day, scope and agent version, `_id = "{day}:{scope}:{agent_version}"` — `scope` (`external` = the exclusion set applied, `all` = nothing excluded; both frozen, with the set as it stood at the freeze), `agent_version` (a release, `unknown`, or `*` for every version), `sessions {requested, reached_active, not_reached, pending, by_end_reason [{reached_active, reason, count}], duration_ms, peak_fps, avg_rtt_ms, by_carrier [{carrier, reached_active, duration_ms, peak_fps, avg_rtt_ms}]}` (each a `Dist {n, p50, p90, edges, hist}` — the day's exact nearest-rank percentiles plus a histogram over fixed edges so a window can be pooled; `by_carrier` is P9c, the Active sessions by the carrier they rode, a day frozen before P9c having none), `ttff {dist, hidden, later_attempts, outcomes}` (FR-22's time to first frame over foreground first-attempt paints, **present only when every `agent_logs` record of the day still existed at the freeze**), `crashes` (by the payload's `agentVersion`), `device_days` (`stats_machine_1d.online_minutes > 0`), `computed_at`. Index `(scope, day)`; **no TTL** — counts and percentiles about the product, no org, no device, no person ([growth-observability.md](growth-observability.md#remote-desktop-quality-from-what-is-recorded-p9a)) |
| `growth_alerts` | FR-102 P10: one row per time a rule fired — `{rule, key, fired_at, cleared_at, detail, mailed_on}`. `cleared_at` is an explicit **`null` while open** (never absent): the **partial unique index on `(rule, key)` where `cleared_at` is `$type: "null"`** is the fire's arbiter across pods — at most one open row per rule and key, a recurrence after a clear a new row. `detail` holds days, counts and source names, never a person; `mailed_on` is the UTC day of the one mail (a compare-and-set, at most once per rule and key per day). **90-day TTL** on `fired_at` ([growth-observability.md](growth-observability.md#alerts)) |
| `growth_posts` | FR-102 P8: one row per social post the promotion pipeline pushed — `{platform, platform_id, account, format, url, published_at, key {source, medium, campaign, content}, cost_cents, created_at, updated_at}`; the key normalised as a sign-up's attribution is. **Never the post's text** — the ingest refuses any field that looks like copy. Written by the `saas` ingest route through the core DAO, read by the host's Channels and Campaigns views. Unique `(platform, platform_id)` (a re-push updates), index `published_at`; no TTL (our own content, no person) |
| `growth_post_snapshots` | FR-102 P8: a post's metrics at `T+1d` · `T+7d` · `T+28d` — `{platform, platform_id, snapshot, taken_at, metrics {raw name: number}, received_at}`, the platform's own metric names kept verbatim. | `growth_pulls` | FR-102 P6: one row per `(source, UTC day)` a puller attempted, `_id = "<source>:<YYYY-MM-DD>"` — `status` (`ok` once a pull succeeded, and it stays `ok` through a later failure; `failed` while none has), `pulled_at`, `attempted_at`, `attempts`, `rows`, `error` (a short reason, never a credential), `missing_goal`, `truncated`. | Collection | Purpose · key fields / indexes |
|---|---|
| `agents` | One row per enrolled machine: name, os, version, caps (codecs/transports/rpc), exec policy, status. **Unique `(tenant_id, machine_id)`** — re-enrollment reuses the row. FR-102 P3 adds `install {method, scope, run?}` — how the device was installed, as its enroll said (`wizard` · `script-sh` · `script-ps1` · `msi` · `deb` · `pkg` · `manual` · `container` · `other`; `unknown` when the agent predates the field); written when the row is created, refreshed by a re-enroll only when that request says, absent on rows from before P3. FR-40 adds three records of different trust: `overlay_identity` (the public key + epoch the device last **joined** with, server-verified, stamped on every join), `key_rotation` (the standing order, with `public_key_before`) and `key_rotation_report` (the device's **claim**; a later refusal never overwrites a `rotated` claim for the same order) — see [overlay-key-rotation.md](overlay-key-rotation.md). FR-90 P3-3a adds `vault_key`: the public half of the key the device's daemon holds now for the values the vault will lease to it (standard base64 of 32 bytes), written from **every** hello and empty when the hello carries none or a malformed one; the daemon makes a new key at each start, so the field never outlives the process ([vault.md](vault.md) §9). Two patterns worth knowing when touching this layer:

- **Tombstones over deletes** in `overlay_nodes`: release paths CAS a tombstone
  *first* (the CAS win is the release token), then return the host number to the
  pool, then fan `netmap_delta{removes}` — that order is load-bearing; see the
  address-lease section of [overlay-communication.md](overlay-communication.md).
- **Hand-built updates must name every field** — the DAO layer builds `doc!{}`
  updates explicitly, so adding a model field means adding it to the DAO update or
  it silently never persists.

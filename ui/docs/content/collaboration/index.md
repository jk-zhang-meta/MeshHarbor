The collaboration layer runs on the same accounts, the same organizations and
the same server as everything else. It is **included in every plan** rather than
sold separately, because it costs us nothing extra to run it next to what is
already there.

:::cards
- **[Rooms and chat](/docs/collaboration/rooms-and-chat/)** icon:video — Organised rooms, threaded replies, reactions, mentions and search.
- **[Video conferencing](/docs/collaboration/video-conferencing/)** icon:monitor — HD calls with screen sharing and recording.
- **[Files](/docs/collaboration/files/)** icon:copy — Attachments, per-room libraries and full-text search.
- **[Notifications](/docs/collaboration/notifications/)** icon:info — Who gets told what, and where.
:::

## Why it is here at all

It is a fair question for a remote-access product. Two reasons, both practical:

:::badges
- **The context is already there** icon:check — the people who need to talk about a machine are the people with access to it, in the same workspace.
- **One account, one bill, one audit trail** icon:shield — rather than a second product with its own identity system next to the first.
:::

If you already have Slack or Teams, you do not have to use any of this — the
remote-access and networking pillars stand entirely on their own.

## What it is not

- **Not a Slack replacement** for a large organization. There are no third-party app integrations, and no workflow platform.
- **Not a webinar tool.** Calls are meetings, not broadcasts to hundreds.
- **Not a document editor.** Files are shared and searched, not co-edited.

Being clear about that is more useful than overselling it.
